# 管理后端开发规则

完整遵循[用户后端开发规则](../../../happyAnyway-api/docs/rules/development.md) DEV-01 至 DEV-07，不复制另一套公共规范。规则由项目经理统一维护，变更时核对两个后端的影响。

## 适用范围与权威来源

- 技术栈、分层和系统边界以[本工程路书](../../ARCHITECTURE.md)为准；依赖版本沿用用户后端实际 pom.xml 基线，升级时统一评估两端影响，不重复逐项确认已确定选型。
- 引用规则中的“本工程”、README、ARCHITECTURE、源码、测试及 docs/development/ 均指 happyAnyway-admin-api 的对应位置，不授权修改用户后端。
- 公共交付流程使用根 docs/rules/；业务需求、接口及表归属仍以已确认方案为准，不因沿用工具预建业务模块或数据读写功能。
- 数据访问沿用 MyBatis，不引入另一套 ORM；Mapper 接口按业务模块组织，SQL XML 位于 resources/mapper/，业务服务通过 Mapper 访问数据。

## 独立部署与共库约束

业务功能、账号权限、凭据、端口及部署环境分别维护，不能直接照搬用户后端运行值。共库运行账号按各自所需表及操作授权，不因技术共用扩大权限。

Flyway 迁移统一协调版本与执行入口，不复制两份相同迁移，也不让两个独立迁移序列争用同一历史表。迁移权限单独安排，不为迁移放大运行账号权限。

实际工程及验证命令建立后按公共规范执行自检；仅有文档骨架时不宣称 Maven 构建或接口验证通过。
