# 管理后台开发规则

技术栈：Vue 3 + TypeScript + Vite + Element Plus + Vue Router + Pinia + Axios。组件、页面和业务逻辑使用明确的 TypeScript 类型，外部 API 响应先校验，不用 any、强制断言或关闭类型检查掩盖问题。使用 Vite 开发与构建，通用界面优先使用 Element Plus 组件，不引入第二套组件库或预建无需求的组件封装；命令以生成后的实际工程为准。类型检查须独立执行，不能把 Vite 构建成功视为 TypeScript 类型检查通过。

1. 开工前确认技术栈、任务范围、接口契约、权限要求、隔离目录与基线，只实现获批功能。
2. 页面负责展示交互，功能服务组织操作，API 层负责契约及响应校验；网络请求通过统一封装，页面不散落请求逻辑。
3. 界面处理加载、空数据、失败和重试；避免重复提交。列表、表单及响应式布局按已确认验收条件实现。
4. 服务端为权限与业务校验的权威来源，不以隐藏入口替代授权。认证、会话和凭据存储方案确认后实施，不在客户端或日志放密钥。
5. 样式、组件与依赖沿用已确认方案，不引入无需求的框架；锁定依赖并记录必要环境变量及使用条件。
6. 用实际工程脚本做静态检查、相关自动化测试和构建，浏览器验证实际交互；构建成功不代表接口联调或权限验证通过。
7. 按页面或功能更新 docs/development/，简述用途、相关文件及职责。每次文件增删或移动同步更新 ARCHITECTURE.md 目录树和文件说明。
8. 交付按[公共执行规则](../../../docs/rules/persistent-agent-development.md)，测试问题由原开发者修复并交独立复测，不自行宣称审查或用户验收通过。

页面导航使用 Vue Router，路由配置集中维护；按实际页面需求定义路由，不预建业务页面。路由守卫用于导航和访问体验，不能替代管理后端的认证授权。

跨页面共享状态使用 Pinia，仅在实际需求出现时建立对应 store；页面局部状态保留在组件中，不预建空状态模块，不默认将状态持久化或存放认证凭据。

HTTP 请求使用统一 Axios 实例，集中管理基础地址、超时、取消及错误分类；页面不直接创建实例或散落请求。API 层定义契约并校验外部响应，界面按错误类型展示可理解提示，避免重复弹错。失败不自动重试写操作；认证信息携带方式待认证方案确认后实现，不预设令牌存储或刷新机制。

代码质量工具已确认：ESLint + Prettier。ESLint 用于代码规范检查，Prettier 用于统一格式；生成工程时配置适用于 Vue 3 与 TypeScript 的规则并避免格式规则冲突。交付执行代码检查、格式检查、独立类型检查及构建，不以其中一项替代其他检查。当前尚未创建工具配置或运行检查。

单元与组件测试方案已确认：Vitest + Vue Test Utils。围绕实际业务行为、组件交互及异常分支编写测试；不预建无功能的测试，不以仅验证模拟调用的断言代替行为验证。组件测试不能代替真实浏览器、接口联调或权限验证。生成工程时再建立实际依赖和执行脚本，当前不宣称测试已运行。

浏览器端到端测试使用 Playwright，按已确认功能验证关键页面流程、交互和失败路径；使用隔离测试环境与数据，不对生产数据执行破坏性操作。依赖、浏览器及测试脚本在工程建立时配置，未执行或受阻项如实说明。模拟接口场景与真实后端联调明确区分，不能互相替代。
