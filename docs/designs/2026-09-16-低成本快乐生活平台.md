# 低成本快乐生活平台首版设计

状态：V1 已确认。用户在本任务中回复“同意”，确认按本方案继续任务拆解（2026-09-16）；包含方案 A、默认规则和阶段顺序。未核验外部资源仍按第 7 节处理。
日期：2026-09-16。路径：新功能设计，基于现有微信小程序、Spring Boot 后端工程。

## 1. 目标与已确认范围

帮助用户发现、分享花很少的钱也能获得快乐和充实感的具体生活体验。生活方式分享是核心，同城、附近和预算是发现同一批内容的入口。首版关注“发现内容—收藏或交流—自己尝试—分享经验”的使用过程。

用户在本次对话中逐项确认：
- 所有用户均可发布，以图文为主；经历、做法和注意事项统一写在正文。
- 金额为本次体验的人均总花费，明细选填，免费填 0。
- 支持手动选择城市及定位查看附近。
- 支持预设预算档位及自定义金额上限，可结合城市筛选。
- 固定分类加自由标签。
- 单列大图信息流，首页默认近期热门。
- 点赞、收藏、评论、关注作者，以及从作者主页发起的一对一文字私信；支持屏蔽和举报。
- 图文检查通过后自动公开，异常进入人工审核。
- 游客可浏览，发布和互动时微信登录。
- 配套精简网页后台，处理审核、举报、违规账号和分类。
- 视觉温暖、轻松、有生活感。
- 已有小程序 AppID；具体值、主体及可用能力尚未核验。

首版不包含视频、图片私信、群聊、交易支付、商家入驻、优惠券或个性化推荐模型。以上不包含项随整体方案确认。

## 2. 实现方案比较

| 方案 | 做法 | 优点 | 代价与风险 |
|---|---|---|---|
| A：现有后端统一承载，另建轻量管理网页（推荐） | 微信端和管理端使用现有后端，业务数据使用 MySQL；图片、地点及内容检查按需接外部服务 | 沿用现有工程，权限、审核、内容状态集中管理 | 需要服务部署、图片存储及外部能力配置；私信和审核仍有明确开发量 |
| B：新建托管后端方案 | 改用托管的数据、身份和函数能力，另建管理网页 | 可减少部分基础设施维护工作 | 需重新评估现有后端投入、供应商限制与费用，存在迁移及绑定成本 |

建议选择 A。现阶段没有足够依据承诺工期或服务费用。外部服务供应商、能力权限及接口限制在实施前核验，不把假定能力当作已具备。

## 3. 首版默认规则（V1 已确认）

以下建议已随整体方案获得用户确认。

### 内容与发布
- 必填标题、正文、1—9 张图片、人均花费和一个分类；最多 5 个标签。建议标题最多 40 字、正文最多 3000 字、单个标签最多 12 字。
- 花费使用人民币，最多两位小数，后端按整数分存储；建议范围 0—99999.99 元。花费由作者自报，包含实际体验支出，正文说明特殊条件和可选明细。
- 预算档位为免费、10 元以内、30 元以内、50 元以内、100 元以内，以及不限；所有上限包含边界值。自定义上限覆盖预设选择。
- 初始分类：美食、出游、运动、兴趣、居家、其他；后台停用分类后不能用于新发布，历史内容保留原分类记录。
- 地点可选：不限地点、仅城市、城市加具体地点。仅有城市的帖子参与同城筛选；有坐标的帖子才参与附近筛选。
- 管理员下架的帖子允许作者修改重提；重新提交仍不公开，必须经人工审核通过后才能重新公开，自动检查通过不能替代该人工决定（2026-09-16 用户明确确认）。
- 作者可编辑、删除自己的内容。编辑公开内容后整篇重新进入审核，审核期间不公开；删除后从信息流、收藏详情和作者主页隐藏，历史引用显示不可用。
- 发布成功先进入待检查；所有文字与图片检查通过后公开。异常转人工；检查失败保持待检查并允许重试，不自动公开。人工拒绝显示原因，作者可修改重提。

### 发现与排序
- 首页默认不限城市，使用近期热门排序；顶部提供城市、预算、分类筛选及附近入口。
- 热门建议采用可解释规则：最近 30 天内的公开帖子，分数为（点赞人数 + 3×收藏人数 + 2×有效评论人数）÷（发布小时数 + 24）。作者自身互动不计分，每位评论者只计一次；按分数、发布时间、ID 依次排序。无候选内容时显示空态，不静默放宽筛选。
- 支持切换最新排序；关注页按所关注作者的公开内容发布时间倒序展示。
- 附近以用户当前授权位置为中心，默认 5 公里，可选 1、5、10、20 公里，按距离、发布时间、ID 排序。附近模式替代城市范围，预算与分类仍生效。
- 拒绝定位时可继续浏览和手动选城市；附近入口说明需要定位。位置仅用于本次查询，不公开用户实时位置；发帖地点由作者主动选择。
- 标题和正文关键词搜索纳入建议范围；筛选条件共同生效，搜索结果默认按近期热门，也可切换最新。

### 登录、互动和私信
- 登录后使用站内昵称和头像，不要求公开真实姓名或手机号；微信身份仅供后端绑定账户，凭据不进入页面或日志。
- 点赞、收藏、关注均可取消，重复请求不会重复计数；自己的收藏列表仅自己可见。
- 评论首版采用平铺文字列表，可删除自己的评论，无嵌套回复；评论检查通过才公开。评论异常转人工，服务失败保留待检查状态。
- 私信只支持文字，建议每条最多 1000 字，显示发送中、已发送、失败；重试不重复创建消息。首版不做已读回执、撤回和系统推送，进入会话时加载并在前台刷新。
- 陌生人可以发起会话；任一方屏蔽后双方不能继续发消息，可解除屏蔽；历史消息保留。会话内容只对参与双方可见。
- 私信内容检查通过再投递；异常拒绝发送，检查服务不可用显示待检查，不绕过检查投递。普通管理列表不展示完整私信；举报处理只展示被举报消息及必要上下文，并记录访问操作。
- 发布、评论、私信均设置服务端频率限制；具体阈值进入接口规格，避免重复提交与批量骚扰。
- 举报覆盖帖子、评论、私信和账号；举报者可查看受理状态。后台支持驳回举报、下架内容、禁言、封禁及解除；被封禁账号不能继续通过旧会话执行受限操作。

## 4. 页面与主要流程

小程序建议四个底部入口：发现、关注、消息、我的；发现页提供明显的发布按钮。

| 页面 | 主要内容 |
|---|---|
| 发现 | 单列图文卡片、热度/最新排序、搜索、预算/城市/分类筛选、附近入口 |
| 内容详情 | 完整图文、人均花费、标签与可选地点、作者、点赞收藏评论、举报 |
| 发布/编辑 | 图文、分类标签、花费、可选地点、提交结果与审核状态 |
| 作者主页 | 头像昵称、公开分享、关注、发私信与举报/屏蔽入口 |
| 关注 | 关注作者的公开内容，未登录或未关注时有明确引导 |
| 消息 | 会话列表、未读数、文字会话、发送结果、屏蔽和举报 |
| 我的 | 自己的帖子及审核状态、收藏、关注列表、屏蔽列表、账号资料 |
| 网页管理后台 | 管理员登录、待审核列表及详情、举报处理、账号状态、分类、操作日志 |

主流程：游客浏览筛选 → 查看详情 → 发起互动时登录 → 返回原页面继续操作；发布 → 检查 → 公开或人工审核 → 向作者展示结果；举报 → 管理员核实 → 处理并记录依据。

视觉建议：米白背景、柔和橙黄点缀、清晰正文和宽松间距，图片为视觉主体；金额清晰但不压过生活内容。加载、空结果、网络失败、内容下架和账号限制分别提示。

## 5. 数据、接口与权限边界

主要数据：用户、帖子、帖子图片、分类、标签、城市/地点、点赞、收藏、关注、评论、会话、消息、屏蔽关系、审核记录、举报及管理操作日志。

接口按账户、内容查询与发布、互动、地点查询、会话消息、举报、管理员操作划分。开发前锁定字段、分页游标、排序、状态码、幂等方式和状态流转契约；金额精度、公开状态与权限由服务端校验。

- 游客只能读取公开内容；作者能读取自己的待审核或拒绝内容。
- 修改与删除验证所有权；私信验证参与者身份和屏蔽状态，不能按任意用户 ID 读取会话。
- 审核回调需要校验来源并幂等处理，过期结果不得覆盖新版内容；已下架或已删除内容不能被旧回调重新公开。
- 图片上传限定类型、大小和数量；待审核原图不通过公开链接泄露，删除和失败上传的清理由授权任务处理。
- 管理员与普通用户权限独立；管理员账号通过部署流程创建，不提供公开注册，写操作和敏感访问留审计记录。
