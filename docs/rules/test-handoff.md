# 第六步：交接独立测试

本文件供项目经理使用，只规定如何交接、接收结果和转派问题。具体测试方法由独立测试 Agent 阅读[独立测试与系统排障规则](../../tests/rules.md)执行。

## 1. 确认交接条件

- 第五步审查已通过，结论对应本次交付版本；阻塞问题已关闭，剩余风险清楚。
- 接收者是已核实的独立测试 Agent，不是本次业务代码的实现者。使用独立持久化任务，遵循[测试 Agent 配置](../../tests/agent.md)，不创建子 Agent 补位。
- 确认测试目录、可访问材料和允许编写测试的范围；环境缺口如实交代，不能预先标记测试就绪或通过。

## 2. 一次性交付所需材料

| 材料 | 交接内容 |
|---|---|
| 任务与范围 | 所属计划、待测功能、做与不做、优先级 |
| 验收依据 | 用户已确认的需求、方案、逐项验收条件和接口约定 |
| 确切版本 | 两端各自的提交、分支、工作目录及完整交付范围；未提交内容提供可核对快照或差异 |
| 审查与自检 | 审查结论、整改复审记录、开发测试报告、已知问题和未验证项 |
| 环境 | 启动方式、测试环境、数据库与小程序条件、测试数据及必要访问方式；不在文档或消息中写真实密钥 |
| 执行规则 | 独立测试与系统排障规则的位置、允许修改的测试和报告路径 |
| 回报要求 | 报告保存位置、验收逐项结果、缺陷证据、环境阻塞和复测结果 |

发给测试 Agent 的消息应包含任务身份和上述材料位置，并要求先确认资料、版本、范围和可执行条件，再开始独立验证。下发及接收结果记在已有计划执行记录中。

## 3. 接收结果并安排下一步

- 收到缺陷：将复现步骤、证据、影响和待复测用例交回原后端或微信开发 Agent；项目经理不代修代码。
- 收到修复：按第五步核实受影响改动的复审结果，再将新版本与变更范围交独立测试 Agent 复测，不能用开发自检关闭测试缺陷。
- 收到阻塞或验收歧义：协调所需材料和环境；影响已确认业务取舍时交用户决定。
- 收到完成报告：核对报告是否对应实际版本、验收项是否都有结果、缺陷是否关闭、未验证项与风险是否明确，再交第七步“用户验收后合并分支”。有未验证项时如实提交，不称为全部通过。

**交接结果：独立测试 Agent 已确认接单，测试范围、版本、材料、规则和报告位置明确；测试是否通过以其后续实际报告为准。**
