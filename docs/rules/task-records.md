# 项目记录规则

确认依据：2026-10-08 用户同意“一个项目总览＋每项交付一份任务记录＋按需证据”。本规则统一记录载体；其他流程中关于单独计划、执行记录、报告、归档文件的旧要求按本规则收敛，职责分离、确认和验证条件保持有效。

轻量任务按 [AGENTS.md 的流程适用范围](../../AGENTS.md#流程适用范围)执行：不强制建立任务文档、循环记录或归档，直接更新目标资料并汇报结果即可。已有任务记录只同步必要状态，不为本次规则调整另建文件；下文完整生命周期用于需要正式跟踪的交付。

## 一个日常入口

根 PROJECT.md 由项目经理维护，只列目标、当前进展、阻塞、待用户决定事项、最新可验收成果和任务链接。每次状态实质变化后更新，结论用人类可读语言；不放长日志、哈希清单或派工全文。结论与任务记录不一致时先核实并修正，不能自动采用较乐观状态。

## 任务目录与生命周期

采用用户最新确认的结构，不再设置 task/ 或单独的当前任务记录文件夹：

```text
docs/plans/
└── 当前任务记录.md  # 唯一的执行、审查、测试和整改循环记录
```

进行中的需求方案、已确认计划及执行、审查、测试和整改循环统一写入 docs/plans/当前任务记录.md，按任务分节，稳定方案与计划和逐轮过程分开组织。项目经理负责汇入，其他岗位反馈内容，不并发改写。完成后才将最终成果提纯到 docs/plans/<任务名>.md；进行中不另建同义计划文件，也不双写方案和计划。长期复用的重要设计与必要独立证据仍按需单独保存并引用，不复制正文。不能为每轮创建独立人工报告；工具原始输出和已有证据仅在必要时引用。

任务完成后，将最终实现、确切版本与验收结论、开发文档入口、仍有效的限制及遗留事项提纯到对应任务文档，删除当前记录中该任务的过程段落；没有活跃任务时只保留“当前无进行中任务”。保留这个文件供下一任务复用，不反复删除新建。已解决 BUG 和排障流水不进入最终文档，有长期价值的经验转为测试、注释或已确认规则。

暂停、阻塞或尚未验收的任务保留必要过程。多个活跃任务在同一文件内分节，完成时只清理对应段落。后续修改功能先读开发文档和代码，不要求重读历史过程。

## 开发说明

每个开发工程使用自己的 docs/development/ 文件夹保存开发文档，由该工程开发 Agent 编写维护，README.md 作为索引。按页面或功能命名文档（例如 backend-connection.md），同一功能持续更新同一文件，不按日期、任务或整改轮次重复建文档。内容由实际开发者负责，项目经理核对；任务记录只链接文档，不保存其正文。新工程同样执行，停用工程保留入口并标明状态。

先用一句话说明页面或功能用途，再按以下三列列出当前实现对应关系；最近变更简要标明新增、修改或删除：

| 使用页面或功能 | 新增、修改、删除的文件 | 文件用途或本次变化 |
|---|---|---|
| 实际页面名或功能名；公共能力写清服务对象 | 使用可点击的准确文件路径并标明变更类型 | 一句话说明职责及变化 |

按页面或功能分组，同一用途的多个文件可合并一行；跨功能公共文件列一次并注明服务对象。覆盖该功能相关的手写源码、测试、配置和脚本，不粘贴代码或逐函数罗列；依赖清单及锁文件可合并说明，自动生成的文件和构建产物只说明类别及位置。后端没有对应页面时写实际接口或功能，不编造页面归属。

需要配置或操作才能使用时，补充一两句入口、必要条件或已有 README 链接；末尾简述已验证结果与未完成项，不重复整份测试报告。后续整改更新受影响行，保持说明对应当前交付版本。简洁不等于只写“修改若干文件”或省略用途。

## 独立结论与按需证据

测试交付采用[问题清单](../../tests/rules.md#6-缺陷记录复测与报告)：只记录发现的问题及复现方法，不汇编通过项或测试流水；无问题时简述，阻塞或未执行范围如实说明。复测更新原问题，不另建总结。必要的原始证据按需保留，不重复转写成人工文档。

项目经理是主工作区任务记录的唯一写入者。开发、审查和测试保持独立，返回各自带身份、版本及依据的结论，经理注明来源汇入记录，不代签通过。需要审查者直接写入时，仅授权任务记录的指定章节并串行安排，避免并发覆盖。

日志、复现脚本、较长审查问题或必须固定的版本清单才单独保存，人工循环结论写入 docs/plans/当前任务记录.md 对应章节，必要的工具原始证据按交接指定位置保留；测试脚本继续遵循 tests/ 的既有归属。短结论不强制另建报告，消息可作为输入，经理核对后将必要结论保存到任务记录。详细证据只链接不抄录，明确验证范围和未验证项。

当前未完成交付的旧材料通过过程记录引用，尚不清理；新增人工循环产出统一写入当前任务记录文件。收尾时按任务归属提纯与清理旧过程材料，保持仍有效的设计和代码依据。固定审查快照在验证期间不得改写；不保存凭据或敏感日志。

## 验收记录方式

检查总览是否能直接回答“完成什么、卡在哪里、需要我做什么、何处验收”；核对任务记录的版本、独立结论和证据链接。此次规则调整和后续同类文档小改动就地记录，不再为减少文档数量另建计划、报告及归档三套文件。
