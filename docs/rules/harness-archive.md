# 第八步：任务记录提纯与收尾

按用户确认的[记录结构](task-records.md)执行：docs/plans/ 下保存提纯后的任务文档，docs/plans/当前任务记录.md 作为唯一文件保存进行中的循环产出。

## 提纯时点与内容

核实用户验收、应有的合并及合并后验证已完成后正常收尾。暂停、受阻或取消不得标为完成，需要恢复的过程材料继续保留。

项目经理将最终目标与实现、交付版本与验收结论、开发文档入口、仍有效的限制和遗留事项写入 docs/plans/<任务名>.md。各工程开发文档持续维护，不复制正文。已修复并复测通过的问题、失败尝试、中间方案和逐轮报告不进入最终文档；有长期价值的经验转为测试、必要注释或经用户确认的规则。未解决及未验证事项不可因提纯自动关闭。

## 清理与交接

每次清理过程文件，同步更新总路书的文件路径、用途及引用；删除操作与路书更新一并核对，不保留失效入口。

核对提纯内容对应最终成果、必要链接可用、仍需使用的材料已安置后，清理 docs/plans/当前任务记录.md 中属于本任务的过程段落；文件保留供复用，无活跃任务时注明“当前无进行中任务”。这是用户已确认流程的一部分，不重复询问。删除前逐项核对实际绝对路径及任务归属，不递归清空整个共享目录，不删除其他活跃任务、源码、回归测试、开发文档或仍需交付的安装包。

仍被有效资料引用的必要内容先更新引用或保留。旧位置的本任务过程材料在核对归属和依赖后同样清理，不把整个历史资料目录视为删除范围。

更新 PROJECT.md 指向提纯文档，结束活跃状态。不自动提交、推送、删除分支或移除 worktree，这些仍按各自授权执行。
