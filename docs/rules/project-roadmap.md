# 项目结构路书维护规则

确认依据：用户于 2026-10-08 要求“每个项目都应该有可维护的项目结构路书”。本规则适用于当前仓库及其后续新增工程，不自动修改仓库外其他项目。

## 入口与内容

每个工程以根目录 ARCHITECTURE.md 为结构路书，README.md 链接该入口；已有结构文档直接补充，不再维护重复目录清单。仓库根 ARCHITECTURE.md 负责工程关系及资料导航，各工程路书负责内部结构。运行命令、接口细节和交付历史链接对应权威资料，不重复抄录。

根路书不保存任务进度、活跃或空闲状态、执行结果和待办；这些信息由 PROJECT.md 和 docs/plans/当前任务记录.md 承载，根路书只保留入口及用途。工程停用标记、实际与规划结构的区分仍保留，不视为任务进度。仅任务状态变化或清理过程段落，且文件路径、用途和结构不变时，无须同步修改根路书。

按项目归属保存：根路书只保存根项目的文件、公共 docs/ 和 docs/plans/ 结构；用户后端、管理后端、App、管理后台前端、小程序和测试目录在根目录树中只保留入口，不展开内部文件。各自的完整目录树仅放在各自 ARCHITECTURE.md。子工程内部文件增删只更新该工程路书；仅工程入口、名称、位置或跨工程关系改变时同步更新根路书，不在根路书复制子工程内容。

路书至少说明：

- 工程用途、边界、维护岗位、最近核对日期和对应代码状态。
- 实际存在的主要目录与职责、关键入口；规划结构与现有实现分开标记，忽略依赖和生成产物。
- 主要调用或数据流、允许与禁止的依赖方向、跨工程接口入口。
- 常见改动应落在哪一层，以及相关测试、配置、运行和构建说明的位置。
- 当前限制、未落地结构和已停用部分；重要取舍链接设计依据。

路书用简洁的路径和一句话用途维护当前文件结构，不写创建、删除的历史流水，不为满足示意图创建空目录。未验证的路径或行为明确标注，不能把隔离工作区成果写成已经合并。

## 维护责任与时机

实际目录树中的每个文件必须在同一行用简洁中文说明用途，例如 `config.ts  # 配置后端请求基础地址`，不能只列文件名或笼统写“配置文件”。说明以实际内容为依据；同名文件按所在目录区分职责。每次增删、移动或职责变化同步维护文件节点与用途，审查逐项核对。子工程文件用途只写在其自身路书，根路书不重复展开。

路书必须包含与实际文件位置一致的目录树。每次创建、删除、移动或重命名文件和目录，同步修改目录树中的节点、层级和名称，并更新用途与链接；只改文字说明不算完成。总路书展示公共资料及工程位置，各工程路书展示内部文件结构；README 链接权威目录树，避免重复维护过时副本。实际结构与规划结构分开展示，不能把未落地路径放进实际目录树。交付和收尾时对照文件系统检查目录树。

各开发工程须有 docs/development/ 及其 README.md 索引，由开发岗位按页面或功能维护简洁开发文档。路书链接该入口，不复制功能文件清单；任务记录只引用开发文档，具体内容要求见[开发说明规则](task-records.md#开发说明)。

项目经理维护总路书及公共规则；开发岗位维护所属工程路书；独立测试岗位维护 tests/ARCHITECTURE.md。轻量任务中，项目经理可直接整理各工程路书文字、去重及修正引用，无须仅为文档维护调用对应岗位；业务结构设计或实现变更仍按职责处理。停用工程标注冻结状态，重新启用时再核对。

新增工程时建立路书。每次创建、删除、移动或重命名文件，都必须在同一次变更中同步更新所属工程的 ARCHITECTURE.md；源码、测试、配置、脚本、开发文档及任务过程文件均适用，不以“只是小文件”或“不是主要目录”为由跳过。根目录及公共资料由项目经理更新总路书；跨工程变动更新相关各方路书。

创建文件时补充路径和用途；删除文件时移除失效条目与引用；移动或重命名时替换路径并核对链接。收尾清理涉及文件增删、移动、重命名或用途变化时同步更新总路书；仅清理 docs/plans/当前任务记录.md 内的过程段落不更新总路书。已有文件内容修改若影响职责、入口、依赖或使用方式，也同步更新；仅内容微调且结构与职责不变时可说明无须更新。

依赖安装和构建自动生成的大量文件按所属目录及生成、清理规则集中描述，创建或删除这类产物时核对并更新对应目录的状态，不逐个罗列缓存文件。一次批量文件操作可集中更新一次路书，但不能拖到后续任务。

接单时读取总路书和相关工程路书，并核对实际工作区。派工明确路书修改范围；审查核对文档与确切交付版本一致，测试核对涉及的运行和验证入口；合并后项目经理核对总入口与最终状态。路书存在缺漏时由对应维护岗位补齐，不以聊天记忆代替。

核对方式为路径与链接检查、目录职责及调用方向对照源码、涉及命令与工程配置比对。只宣称实际执行过的验证；文档校验不代表构建或功能测试通过。结构漂移影响接手或正确实施时，交回责任岗位修正后再放行受影响交付。
