# App 开发规则

1. 开工核对已确认方案、计划、隔离目录和基线。只处理获派范围，不引入未确认业务。
2. TypeScript 类型明确；外部响应先校验，不以 any、类型断言或关闭检查掩盖问题。请求与平台调用遵循 ARCHITECTURE.md。
3. 页面包含待检查、加载、成功、失败状态。加载中阻止重复请求；超时与失败后恢复可操作；卸载后释放资源，不允许旧响应覆盖新状态。不自动无限重试。
4. 网络配置区分测试与发布。缺少地址明确报错，不能默认访问手机的 localhost，也不能静默使用假数据。HTTP 例外和局域网权限只用于显式测试配置，发布配置要求 HTTPS。
5. 密钥、签名材料、令牌不进入仓库或日志；日志仅保留必要错误分类。客户端环境变量不是保密机制。
6. 依赖使用 Expo 兼容组合和锁文件，查询官方来源记录选择依据；不使用动态版本，不做无关升级。原生模块通过 Expo 配置插件/可再生配置维护，说明生成目录策略。
7. 关键模块与公开函数以简洁中文说明职责、输入输出和异常；复杂资源清理说明原因，不逐行注释。
8. 测试覆盖真实行为和异常分支，不写仅镜像实现的断言。静态检查、JS 导出、原生构建、安装、设备测试分别记录；不能互相替代。
9. Windows 本地 Android 构建；iOS EAS 云构建。账号、签名、设备注册不足时标明阻塞；不替用户认证或购买服务。云上传前核对排除项。
10. 报告按公共执行规则，审查/测试整改由本岗位处理。项目经理不代写 App 实现。
11. 交付时由开发者编写[开发说明](../../../docs/rules/task-records.md#开发说明)，按页面或功能简明列出变更文件及用途，必要时补充使用入口和条件，保存到本工程 docs/development/ 并维护索引，任务记录只链接。
